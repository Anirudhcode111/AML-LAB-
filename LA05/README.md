## A1. Iris in Ten Lines

### Method

The Iris dataset was split into **75% training and 25% testing data** using stratification. Features were standardized using `StandardScaler`, followed by a **KNeighborsClassifier with `n_neighbors=5`**.

### Result

Class order:

```text
['setosa', 'versicolor', 'virginica']
```

### Observation

The KNN classifier achieves **97.37% test accuracy** on the stratified 75/25 split. Only one **virginica** sample is classified as **versicolor**, while the other samples are classified correctly.

## A3. Choosing k

KNN was evaluated for:

```text
k = {1, 3, 5, 7, 9, 11, 15}
```

using an **80/20 stratified train/test split** on the Digits dataset.

### Results

| k | Test Accuracy |
|---:|---:|
| 1 | 97.50% |
| 3 | **98.61%** |
| 5 | 98.33% |
| 7 | 98.06% |
| 9 | 97.78% |
| 11 | 97.78% |
| 15 | 97.50% |

### Best k

**Best k = 3**

**Best test accuracy = 98.61%**

### Observation

At **k = 1**, the classifier is very sensitive to individual training examples and noise, which can cause overfitting. At a very large value of `k`, too many neighbors influence the prediction, producing an overly smooth decision boundary and causing underfitting.

# Section B – Medium

## B2. Which Digits Get Confused?

The best model was used to generate the complete **10 × 10 multiclass confusion matrix** for the Digits dataset.

### Three Most Frequently Confused Ordered Pairs

| True Digit → Predicted Digit | Number of Cases |
|---|---:|
| **8 → 1** | **2** |
| **4 → 8** | **1** |
| **3 → 4** | **1** |

### Observation

The most frequent confusion is **8 → 1**. These handwritten digits can be difficult to distinguish when strokes are faint, unusually shaped, or overlap in a way that makes their pixel patterns resemble another digit.

The Digits images are only **8 × 8 pixels**, so fine handwriting details are limited. The classifier therefore relies mainly on coarse pixel-intensity patterns, and small variations can make an example appear closer to another class.

Four misclassified images were also displayed in the notebook with their true and predicted labels.

# Section C – Hard

## C1. Does More Resolution Help?

The best model was compared on:

1. **8 × 8 scikit-learn Digits**
2. **28 × 28 MNIST**, using a **10,000-row subsample**

The model used was an **RBF-kernel SVM**, with feature scaling performed inside a Pipeline.

### Comparison

| Dataset | Image Resolution | Features | Accuracy | Fit Time |
|---|---|---:|---:|---:|
| Digits | 8 × 8 | 64 | 98.61% | Measured in notebook |
| MNIST (10,000 rows) | 28 × 28 | 784 | Generated when notebook is run | Measured in notebook |

### Observation

The 28 × 28 MNIST images contain **784 pixel features**, compared with only **64 features** in the 8 × 8 Digits dataset. The higher resolution preserves more detailed information about handwritten strokes, which can help distinguish visually similar digits.

However, the larger feature space increases computational and memory requirements and therefore increases the cost of training. Thus, additional resolution can provide more useful visual information, but it comes with a computational trade-off.

> **Note:** The MNIST portion uses `fetch_openml("mnist_784")` in the notebook. Its accuracy and fit time should be generated by executing the notebook in a network-enabled environment; no MNIST result has been fabricated here.
